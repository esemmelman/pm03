# Solo

A personal project workspace: quick capture, Today/This week/Backlog/Inbox views, editable tasks with projects, priorities, tags and notes, list and board layouts, project Markdown source notes, scratchpad, a pausable 25-minute focus timer, focus totals, and JSON backup import/export.

Run `npm start` and open http://127.0.0.1:4173. Run `npm run check` and `npm run build` to validate and prepare static files in `dist`.

Choose **Sign in** and use the same DayFlow account on every device to sync projects, tasks (including schedules and completion), project notes, scratchpad, focus logs and tutorial state. Existing local work is adopted on first sign-in; a new browser loads the cloud workspace. Signed-out work remains local. An account-scoped localStorage cache keeps offline changes until reconnection; clearing browser data before changes sync can remove pending edits. Export remains available for backups. Notes are plain text/Markdown and are never rendered as HTML. Subtasks and recurrence are not implemented.

Shortcuts: N creates a task; / searches; Escape closes the task editor. Click a task title to edit or delete it. Focus sessions log 25 minutes when the timer finishes while the app is open; paused or reset sessions are not logged.

Choose **Carnival tutorial** in the header for an eight-step walkthrough of a fictional school carnival. **Add carnival example** adds one project and fourteen editable tasks without replacing current work; repeated clicks reopen the same example. It includes planning milestones, an illustrative budget, volunteer and supply tasks, event-day operations and a wrap-up. Step completion is self-reported and saved with workspace backups. Tutorial tasks use relative milestones in notes; planning buckets do not schedule dates automatically.

Reading text is enlarged throughout: task titles and notes are 17px, with supporting task labels at 14px and tutorial body text at 17px (16px on phones).

Projects appear at the top of the sidebar, including on mobile. Select a project, then use **Tasks** / **Project notes** above the content to switch sections. Notes save while typing. Left/right arrows switch tabs when the tab bar has focus. Global task views show tasks directly. The workspace summary cards and Solo sidebar label have been removed.

Select a project and choose **Edit project** beside its title to change its name and notes. **Delete project** opens a confirmation: by default its tasks are kept as Unassigned with their current planning buckets and completion status. Check **Also delete this project’s tasks** to remove them, including completed tasks. Project notes are removed on deletion; export first to retain a backup. Logged focus time is kept as Unassigned. Use the + beside Projects to create a new project in the same editor.

The **Gantt chart** tab beside Project notes shows all scheduled tasks for the selected project, sorted by start date. Set **Start date** and **End date** in the task editor; both are optional together, and the end must be on or after the start. Bars include both dates (a same-day task lasts one day). Click a bar or task label to edit. Unscheduled tasks appear below the chart with **Set dates** actions. The chart scales to the project’s range and scrolls horizontally; completed bars use a striped fill. Dates are preserved in local storage and JSON backups; older backups without dates remain supported. Date ranges are independent of the Today/This week planning buckets. Gantt dependencies and dragging Gantt bars are not implemented; use Calendar for dragging tasks.


Choose **Schedule** in Task views to plan across projects. Switch between a day and seven days. Set dates for whole-day tasks or add start/end times to schedule to the minute; timed tasks use one date. Each task has an estimated duration (30 minutes by default). The task queue offers **Find a slot**, which saves the earliest free interval on the selected date within your working hours. Completed tasks do not reserve time. Date-only project tasks are day-level plans; DayFlow all-day items reserve the whole day. Edit a task to move it or clear both dates and times to return it to the queue.

**Live DayFlow calendar:** Schedule connects to the same Supabase project as DayFlow using its public browser key and existing per-user row policies. An existing DayFlow session is reused on the same site origin; otherwise choose **Connect DayFlow** and sign in with the same email and password. Calendar changes refresh through Realtime, with a 30-second refresh fallback while the page is visible and refresh when returning to the tab or reconnecting. **Refresh calendar** also refreshes immediately. Find a slot fetches current busy times first and refuses to schedule if the refresh fails. Connection failures are shown beside the calendar.

The connection only reads DayFlow appointments; project tasks sync to the separate `pm03_workspaces` table and are never written into DayFlow appointments. Live calendar data is kept in memory and cleared on sign-out or account changes. Old imported snapshots remain in existing workspace backups for compatibility but are no longer used by the live schedule. Dated DayFlow items without times reserve whole days; items without end times reserve one hour (capped at 23:59). Undated inbox items are omitted. Invalid or overnight intervals stop the refresh with an error rather than silently allowing scheduling over them. Times are interpreted as local wall-clock times.

Supabase browser SDK 2.119.0 is pinned and vendored in `vendor/supabase.js` (MIT license). Run `qa-live.cjs` with `SOLO_JSDOM` pointing to jsdom to test live updates, deletions, failed refreshes, and sign-out during a request, alongside `qa.cjs` and `qa-schedule.cjs`.


The **Calendar** button beside List/Board opens the scheduler directly. It starts with seven dates and a scrollable half-hour time grid, showing live DayFlow appointments in blue and local tasks in yellow. Switch to Day for a single column, or use the date and previous/next controls to navigate. Drag a task from the Tasks list or its calendar block onto a time slot or the All day row. Scheduled tasks keep their duration when moved; date-only plans keep their day span when moved to All day. Use **Place on calendar** followed by clicking/tapping a slot as a keyboard and touch alternative. The editor still supports exact minute-level start/end times.

Date-only project tasks are day-level plans and do not block timed slots; DayFlow all-day appointments do block the day. Timed drops reject overlaps with other timed tasks or DayFlow appointments and tasks extending beyond the day. When signed in, placement refreshes DayFlow before checking conflicts. Without a connected account, local scheduling works with the connection status shown; DayFlow conflicts cannot be checked until connected. **Find a slot** continues to require a successful live calendar refresh.

Quick capture and the New task editor default both dates to the current local date. Quick capture resets the dates to today after each addition. You can clear both dates for an undated task. Run `qa-calendar.cjs` alongside the other checks to verify date defaults, dragging, conflict handling, moving, day spans, click placement and saved schedules.


The compact capture row has an unlabeled title input, two date inputs with accessible names, a + save control and a microphone. Press **Enter** (or +) to save. The microphone captures one English utterance, fills the task title and dates, and waits for review before saving. Examples: “Call Alex tomorrow”, “Prepare report from Monday to Friday”, “Review proposal start date November 9 end date November 12”. Single dates fill both fields; no spoken date keeps the selected dates (today by default). Times are also supported for same-day tasks. Typed natural-language dates are parsed on submission.

Voice recognition uses `SpeechRecognition`/`webkitSpeechRecognition` where available. The browser requests microphone permission; its recognition provider may process audio online. No audio is stored by this app. Unsupported browsers show an explanation and support typing or the device keyboard microphone. English date parsing uses the vendored chrono-node 2.10.0 English bundle (MIT license).

Workspace sync uses private owner-only RLS policies, Supabase Realtime and a 20-second visible-page fallback. The client merges independent edits and uses revision checks to prevent stale writes. A change to the same field on two devices, or deleting an item while another device edits it, pauses sync and offers a version comparison, recovery export and a choice of this device or cloud. Both versions are retained in local recovery snapshots. Sync waits while task/project editors are open. Account switching clears the displayed workspace and retains offline caches under their original account. Check the visible status for **Synced across devices** before relying on another device.

`workspace-schema.sql` records the deployed schema in the existing DayFlow Supabase project. Tests `qa-sync.cjs` and `qa-capture.cjs` exercise independent devices, concurrent edits, deletions, offline reload, conflicts, account isolation, natural-language dates, Enter submission and simulated speech. Set `SOLO_JSDOM` to a jsdom installation when running the DOM checks. Browser QA additionally covers the real vendored Supabase SDK against mocked REST endpoints; real microphone recognition depends on browser support and permission.
