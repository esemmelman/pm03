# Solo

A personal project workspace: quick capture, Today/This week/Backlog/Inbox views, editable tasks with projects, priorities, tags and notes, list and board layouts, project Markdown source notes, scratchpad, a pausable 25-minute focus timer, focus totals, and JSON backup import/export.

Run `npm start` and open http://127.0.0.1:4173. Run `npm run check` and `npm run build` to validate and prepare static files in `dist`.

Choose **Sign in** and use the same DayFlow account on every device to sync projects, tasks (including schedules and completion), project notes, scratchpad, focus logs and tutorial state. Existing local work is adopted on first sign-in; a new browser loads the cloud workspace. Signed-out work remains local. An account-scoped localStorage cache keeps offline changes until reconnection; clearing browser data before changes sync can remove pending edits. Export remains available for backups. Notes are plain text/Markdown and are never rendered as HTML. Subtasks and recurrence are not implemented.

Shortcuts: N creates a task; / searches; Escape closes the task editor. Click a task title to edit or delete it. Focus sessions log 25 minutes when the timer finishes while the app is open; paused or reset sessions are not logged.

Choose **Carnival tutorial** in the header for an eight-step walkthrough of a fictional school carnival. **Add carnival example** adds one project and fourteen editable tasks without replacing current work; repeated clicks reopen the same example. It includes planning milestones, an illustrative budget, volunteer and supply tasks, event-day operations and a wrap-up. Step completion is self-reported and saved with workspace backups. Tutorial tasks use relative milestones in notes; planning buckets do not schedule dates automatically.

Reading text is enlarged throughout: task titles and notes are 17px, with supporting task labels at 14px and tutorial body text at 17px (16px on phones).

Projects appear at the top of the sidebar, including on mobile. Clicking a project name toggles its task titles underneath and opens the calendar. Use **⋯** beside the name to open the project’s Tasks / Project notes / Gantt sections. Use **+** beside a project to add a task to it. Notes save while typing. Left/right arrows switch tabs when the tab bar has focus. Global task views show tasks directly. The workspace summary cards and Solo sidebar label have been removed.

Select a project and choose **Edit project** beside its title to change its name and notes. **Delete project** opens a confirmation: by default its tasks are kept as Unassigned with their current planning buckets and completion status. Check **Also delete this project’s tasks** to remove them, including completed tasks. Project notes are removed on deletion; export first to retain a backup. Logged focus time is kept as Unassigned. Use the + beside Projects to create a new project in the same editor.

The **Gantt chart** tab beside Project notes shows all scheduled tasks for the selected project, sorted by start date. Set **Start date** and **End date** in the task editor; both are optional together, and the end must be on or after the start. Bars include both dates (a same-day task lasts one day). Click a bar or task label to edit. Unscheduled tasks appear below the chart with **Set dates** actions. The chart scales to the project’s range and scrolls horizontally; completed bars use a striped fill. Dates are preserved in local storage and JSON backups; older backups without dates remain supported. Date ranges are independent of the Today/This week planning buckets. Gantt dependencies and dragging Gantt bars are not implemented; use Calendar for dragging tasks.


Choose **Schedule** in Task views to plan across projects. Switch between a day and seven days. Set dates for whole-day tasks or add start/end times to schedule to the minute; timed tasks use one date. Each task has an estimated duration (30 minutes by default). Completed tasks do not reserve time. Date-only tasks and DayFlow entries are day-level plans; timed entries reserve their actual hours. Edit a task to move it or clear both dates and times to leave it undated.

**Live DayFlow calendar:** Schedule connects to the same Supabase project as DayFlow using its public browser key and existing per-user row policies. An existing DayFlow session is reused on the same site origin; otherwise choose **Sign in** in the sidebar and sign in with the same email and password. Calendar changes refresh through Realtime, with a 30-second refresh fallback while the page is visible and refresh when returning to the tab or reconnecting. **Refresh** in the sidebar also refreshes immediately. Placement refreshes current busy times first and refuses to schedule if that refresh fails. Connection details appear under **DayFlow connection** in the sidebar.

DayFlow appointments can be created, edited and deleted through the signed-in account; project tasks sync to the separate `pm03_workspaces` table and are never written into DayFlow appointments. Live calendar data is kept in memory and cleared on sign-out or account changes. Old imported snapshots remain in existing workspace backups for compatibility but are no longer used by the live schedule. Dated DayFlow items without times appear as day plans; items without end times reserve one hour (capped at midnight). Undated inbox items are omitted. Entries whose end time equals or precedes their start are shown at their start time with a one-hour reservation, capped at midnight, and a note to check the time in DayFlow. This matches DayFlow’s date-based display without assuming an overnight appointment or changing source data. A malformed start time reserves the whole day with a warning. An invalid date is reported separately while other appointments load; placement pauses until those dates are corrected. Times are interpreted as local wall-clock times.

Supabase browser SDK 2.119.0 is pinned and vendored in `vendor/supabase.js` (MIT license). Run `qa-live.cjs` with `SOLO_JSDOM` pointing to jsdom to test live updates, deletions, failed refreshes, and sign-out during a request, alongside `qa.cjs` and `qa-schedule.cjs`.


Click a project name, **Calendar** beside List/Board, or **Schedule** in Task views to open a compact calendar beneath the Calendar / Tasks / Project notes / Gantt chart tabs for the selected project. The workspace header, task capture, footer, help text and former right-hand Tasks panel are absent in calendar mode. Date navigation, Day/7 days, account/refresh controls and connection details are in the left sidebar. Times on calendar axes, appointments, tooltips, drop targets and placement feedback use AM/PM; stored scheduling values remain ISO times.

Drag a task title from beneath any expanded project onto a time slot or the All day row. The title stays in the sidebar after placement and the task keeps its project and duration. Multiple project lists can be expanded. Clicking a title selects it for placement by clicking/tapping a calendar slot, supporting touch and keyboard use. Double-click a sidebar title, or press F2 on it, to edit. Completed titles remain visible but cannot be dragged. Calendar blocks can also be dragged to reschedule. Date-only tasks retain their day span when moved to All day. The editor supports exact minute-level times. Phones keep the project list on the left and default to a single day when clicking a project.

Date-only tasks and DayFlow entries are day-level plans. Timed overlap checks use timed tasks and appointments; an invalid start time still reserves the day until corrected. Taken times open an overlap confirmation with **No** focused by default. Pressing Enter or Escape declines; **Yes, place it here** explicitly allows the overlap. Placements extending beyond the day are rejected. When signed in, placement refreshes DayFlow before checking conflicts. Without a connected account, local scheduling works with the connection status shown; DayFlow conflicts cannot be checked until connected.

Quick capture and the New task editor default both dates to the current local date. Quick capture resets the dates to today after each addition. You can clear both dates for an undated task. Run `qa-calendar.cjs` alongside the other checks to verify date defaults, dragging, conflict handling, moving, day spans, click placement and saved schedules.


The compact capture row has an unlabeled title input, two date inputs with accessible names, a + save control and a microphone. Press **Enter** (or +) to save. The microphone captures one English utterance, fills the task title and dates, and waits for review before saving. Examples: “Call Alex tomorrow”, “Prepare report from Monday to Friday”, “Review proposal start date November 9 end date November 12”. Single dates fill both fields; no spoken date keeps the selected dates (today by default). Times are also supported for same-day tasks. Typed natural-language dates are parsed on submission.

Voice recognition uses `SpeechRecognition`/`webkitSpeechRecognition` where available. The browser requests microphone permission; its recognition provider may process audio online. No audio is stored by this app. Unsupported browsers show an explanation and support typing or the device keyboard microphone. English date parsing uses the vendored chrono-node 2.10.0 English bundle (MIT license).

Workspace sync uses private owner-only RLS policies, Supabase Realtime and a 20-second visible-page fallback. The client merges independent edits and uses revision checks to prevent stale writes. A change to the same field on two devices, or deleting an item while another device edits it, pauses sync and offers a version comparison, recovery export and a choice of this device or cloud. Both versions are retained in local recovery snapshots. Sync waits while task/project editors are open. Account switching clears the displayed workspace and retains offline caches under their original account. Check the visible status for **Synced across devices** before relying on another device.

`workspace-schema.sql` records the deployed schema in the existing DayFlow Supabase project. Tests `qa-sync.cjs` and `qa-capture.cjs` exercise independent devices, concurrent edits, deletions, offline reload, conflicts, account isolation, natural-language dates, Enter submission and simulated speech. Set `SOLO_JSDOM` to a jsdom installation when running the DOM checks. Browser QA additionally covers the real vendored Supabase SDK against mocked REST endpoints; real microphone recognition depends on browser support and permission.


The **All day** label under Time is a toggle, initially collapsed. Expand it to see day-level tasks, all-day appointments and the **+ Day plan** targets. “Day plan” means assigning a task to that date without a time; it does not create a separate task by itself. The toggle keeps its state while navigating or refreshing the calendar during the session. DayFlow appointment blocks show their title and time without a repeated source label.


The calendar sidebar is wider (340px on desktop, 280px on medium screens and 176px on phones). The timed grid shows 5:00 AM through the 11:00 PM boundary, omitting overnight rows. Appointments crossing a boundary are clipped to the visible portion while keeping their original times; entirely overnight items remain saved and continue to reserve their actual time.


Drag a scheduled task back onto the project list in the left frame to remove its calendar schedule. Its title, project, notes and estimated duration are preserved. The task editor also has **Remove from calendar**. The Unassigned sidebar group is hidden. Unassigned tasks remain saved and accessible in Task Views; removing their calendar schedule does not delete them.

Calendar task titles end with the project name in parentheses. Task titles in the calendar, sidebar and task list use a single line with ellipses; hover shows the complete title. Calendar task time ranges are available in the hover tooltip. Horizontal calendar dragging preserves the original grab position, so moving a task to another day does not shift its start time. Real timed conflicts identify the conflicting item and date.

Run `qa-planning.cjs` for project-tab navigation, project-name suffixes, cross-day grabbed-time preservation, date-only DayFlow entries, genuine overlap checks, drag-back unscheduling, editor unscheduling, unassigned tasks and persistence.


The right arrow beside the last date heading advances to the next date set (seven dates in week view, one in day view). Click an empty slot with no project task selected to create a DayFlow appointment at that date/time. Click a DayFlow appointment to edit its title, date, all-day status, times or notes, or to delete it. Click a selected sidebar task again, or press Escape, to clear placement selection before creating an appointment.

Appointment writes use the existing owner-only policies on DayFlow’s `tasks` table. Updates preserve color, timezone and reminder settings. Optimistic filters on the original editable values stop stale forms from overwriting another device’s edits. Create retries reuse the same ID to prevent duplicates after a lost response. Delete confirmations also default to No. Account changes close private appointment editors. A fresh read after saving/deleting updates the calendar on this device and DayFlow’s existing sync propagates changes to other devices. Project tasks remain in `pm03_workspaces` and are not automatically copied into appointments.

`qa-dayflow-editor.cjs` covers date navigation, default-No/explicit-Yes overlaps, blank-space creation, owner-scoped updates/deletion, reminder preservation, stale edits, retry idempotence and account isolation. Database CRUD and RLS checks use synthetic records in a rolled-back transaction. Browser QA exercises the real vendored SDK against mocked REST endpoints, including Enter/Escape confirmation behavior and phone layouts.


The workspace opens directly in Calendar view. Task colors indicate calendar scheduling rather than project ownership: sidebar titles without calendar dates use light red (`#ff8a80`) against the dark background; scheduled titles stay white. Unscheduled task-list titles use dark red (`#b42318`) on their light background. Dragging a task onto or off the calendar updates its color immediately. The Unassigned sidebar group remains hidden.
